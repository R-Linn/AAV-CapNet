# 全过程说明

## 1. 总体方法

本次交付不是一次性下载现成统一数据，而是通过多阶段、多轮次的递归整理与复核形成。  
整体过程包括：

- 公开来源发现
- 来源筛选与边界判断
- 结构化抽取
- 字段统一与分桶
- provenance 与证据分层
- 反复增量补齐
- 多轮冻结复核
- 最终交付打包

## 2. 过程阶段

### 第一阶段：需求与边界锁定

- 明确只使用公开可核验来源
- 明确不编造数据
- 明确不把缺失序列或不可比指标强行补齐

### 第二阶段：数据骨架建立

- 建立 AAV sequence、AAV assay、CCLE features、support 层的基本结构
- 搭建可重复执行的整理流程

### 第三阶段：公开来源整合

- 整合公开 AAV 序列与文献信息
- 整合公开 CCLE / DepMap expression、model、RPPA 信息
- 对细胞系名称与标准化匹配做归一化

### 第四阶段：多轮递归补齐

- 对关键 AAV 变体做增量补证
- 对 assay 行与 CCLE 匹配做反复修正
- 对 expression release 做 overlap 比较和筛选
- 对可疑来源做 provenance gate

### 第五阶段：补充材料与结构化判断

- 回溯补充材料、supplementary files、PDF 和 source-data 线索
- 判断哪些材料足以形成正式结构化记录，哪些只能保留为存在证明或辅助证据

### 第六阶段：多轮复核与冻结

- 对当前输出结果做多轮递归复核
- 评估 sequence、assay、CCLE 联通性
- 识别剩余来源边界和统计成熟度限制
- 冻结当前正式可交付结果

### 第七阶段：客户版交付包输出

- 将正式数据、来源摘要与说明文档整理成客户可直接使用的交付包
- 输出中英文两版说明
- 去除内部 audit 和内部决策轨迹

## 3. 过程特点

本交付过程强调：

- 不是一轮粗抓，而是多轮递归增量补齐
- 不是只看“有没有”，而是看“是否足以正式入表”
- 不是只追求更多行数，而是同时控制来源质量和证据边界

## 4. 过程结果

最终形成的是一个：

- 来源可追溯
- 说明完整
- 证据边界明确
- 适合继续扩展

的客户交付包。
